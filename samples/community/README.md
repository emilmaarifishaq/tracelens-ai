# Community sample captures

Real 4G/5G core-network captures, committed directly (unlike everything
else under `samples/`, which is either generated on demand or downloaded
via `download_external_captures.py` -- see
[../../docs/sample-capture-strategy.md](../../docs/sample-capture-strategy.md)
for why that's normally preferred). These are small, contain no payload
data beyond standard control-plane signaling, and are useful as
ready-to-use regression fixtures without needing a generator script or an
external download step.

Each file was decoded through TraceLens end-to-end and manually verified
against `tshark` directly before being added here.

| File | Frames | Protocols | Result |
| --- | --- | --- | --- |
| `nsa_connection.pcap` | 70 | S1AP, Diameter, GTPv2-C | Clean -- all Diameter exchanges return Result-Code 2001 (success), no TraceLens errors |
| `inbound_roaming_01.pcapng` | 240 | S1AP, Diameter, GTP-U, GTPv2-C, ARP | Clean -- same as above |
| `gx_gy_combined_03.pcapng` | 291 | S1AP, Diameter (Gx/Gy), GTP-U, ARP | Clean -- same as above |
| `gx_gy_combined_05.pcapng` | 152 | S1AP, Diameter (Gx/Gy), GTP-U, ARP | Clean -- same as above |
| `gx_gy_combined_06.pcapng` | 143 | S1AP, Diameter (Gx/Gy), GTP-U, ARP | Clean -- same as above |

None of these currently trigger a detected error -- every Diameter
Result-Code/Experimental-Result-Code observed across all 5 files is 2001
(`DIAMETER_SUCCESS`), confirmed directly via
`tshark -T fields -e diameter.Result-Code -e diameter.Experimental-Result-Code`.
They're useful as "decodes correctly, finds nothing wrong" regression
coverage (no crashes, no false positives) across real S1AP/Diameter/GTP
traffic, complementing the synthetic failure fixtures generated by the
`samples/make_*.py` scripts.
